### `src/app/layout.tsx`

```ts

const bitter = Bitter({
  subsets: ["latin"],
  style: ["normal", "italic"],
  variable: "--font-bitter-src",
  display: "swap",
});

const caveat = Caveat({
  subsets: ["latin"],
  variable: "--font-caveat-src",
  display: "swap",
});
```

applied as `<html lang="en" className={`${bitter.variable} ${caveat.variable}`} …>`.
Nothing else in that file was touched (GTM `<Script>`, `antialiased` on `<body>`,
both `suppressHydrationWarning`s all unchanged).

**Two deliberate deviations from the brief, both documented in code comments:**

1. **No `weight` array — the variable fonts are loaded instead.** Both Bitter and
   Caveat are variable fonts on Google Fonts. Listing `weight: ["500","700","800","900"]`
   would make Next fetch four *static* instances (plus a fifth for italic) ≈5 files;
   the variable font is 1 file per style and covers the whole 100–900 axis. Verified
   in-browser: `Bitter | 100 900 | normal | loaded` and `Caveat | 400 700 | normal | loaded`.
   Loading only 700/900 as literally specified would have left the design's 500 and
   800 elements synthesising a weight.
2. **CSS variable named `--font-bitter-src`, not `--font-bitter`.** `next/font` sets
   its variable **on `<html>`**, which *is* `:root`. Tailwind v4's `@theme inline`
   emits the theme key into `:root` too (confirmed by reading the generated CSS —
   `--font-bitter: var(--font-bitter-stack)` is present in the output). Had both used
   the name `--font-bitter`, the token would have referenced itself → a `var()` cycle
   → guaranteed-invalid declaration. The `-src` suffix keeps the raw family name and
   the Tailwind token distinct, mirroring the existing `--font-jetbrains-mono` →
   `--font-mono` convention already in the file.

### `src/app/globals.css`

In `:root`, alongside `--font-raleway` / `--font-jetbrains-mono`:

```css
--font-bitter-stack: var(--font-bitter-src), Georgia, "Times New Roman", serif;
--font-caveat-stack: var(--font-caveat-src), "Segoe Script", "Bradley Hand", cursive;
```

In the existing `@theme inline` block, alongside `--font-sans` / `--font-mono`:

```css
--font-bitter: var(--font-bitter-stack);
--font-caveat: var(--font-caveat-stack);
```

→ `font-bitter` and `font-caveat` are now Tailwind utilities, generated exactly the
way `font-mono` already is.

## Concerns and judgement calls

1. **`MarketPageSections` → 221 (judgement call, flagging rather than hiding).**
   The copy reads *"See all N reviews **across Trustpilot, Google & TripAdvisor**"* —
   an explicitly cross-platform **count**, not a rating. I summed the three rated
   platform counts from the source of truth (51+149+21 = 221) rather than substituting
   the Google-only 149, because 149 would make the sentence false. This does not
   conflict with the owner decision, which governs the aggregate **rating**. If you'd
   rather no cross-platform total appear anywhere, the fix is to change the copy to
   Google-only — that's a product/copy decision, so I did not make it unilaterally.

2. **Unrelated stale hardcoded fallback found in the tour-detail Product JSON-LD —
   not fixed.** `src/app/(website)/tours/from-bali/[slug]/page.tsx:322-323` and the
   `from-surabaya` twin emit, on the per-package `Product` node:
   ```ts
   ratingValue: pkg.aggregateRating?.ratingValue || String(googleStats?.rating ?? 4.8),
   reviewCount: pkg.aggregateRating?.reviewCount || String(googleStats?.count ?? 141),
   ```
   `4.8` / `141` are hardcoded and stale (never sourced from `jvtoReviews.ts`, so
   outside the 11-file brief). Fixing it means deciding whether to drop the whole
   `Product.aggregateRating` node when no source answers — which changes rich-result
   eligibility for every tour page. **Flagging, not guessing.**

3. **Stale metadata fallback string, left alone.**
   `why-jvto/reviews/page.tsx` `generateMetadata()` has a hardcoded fallback
   description: *"Trustpilot 4.8, Google 4.90, TripAdvisor 4.95 … 195+ verified
   reviews"*. The three ratings are all **correct** against the source of truth, and
   "195+" is still true (actual 221). It is only used when the ekosistem page record
   has no description. Not wrong, so not touched — but worth a copy refresh.

4. **`/why-jvto/[slug]`'s `slug === "reviews"` branch is effectively dead.**
   `WHY_JVTO_FOLDER_ROUTED_SLUGS` includes `"reviews"` and the folder route
   `why-jvto/reviews/page.tsx` wins, so `ReviewsAggregateCards` and that schema branch
   never render. I wired them to live data anyway (rather than deleting) so the two
   paths stay consistent — but the dead branch itself is worth a separate cleanup.

5. **`/why-jvto/reviews` has a static heading "Verified across three platforms."**
   Correct today (Trustpilot, Google Maps, TripAdvisor are the three rated profiles;
   GetYourGuide has `null` rating and is filtered out). If a fourth platform ever gets
   a rating in `review-platforms.json`, that heading and the `.slice(0, 3)` calls will
   need revisiting.

6. **Pre-existing site-wide font gap remains.** `--font-raleway`, `--font-inter` and
   `--font-jetbrains-mono` are still CSS stacks with nothing fetching those typefaces,
   so `font-display`, `font-sans` and `font-mono` still fall through to system fallbacks
   across the whole site. Out of scope per the brief, but now that `next/font/google`
   is wired into the root layout, closing it is a small follow-up.
