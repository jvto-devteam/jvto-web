### Styling approach

Every inline style in the export was converted to Tailwind utilities. Design-token colours map to the
project's `@theme` tokens (`jvto-navy`, `jvto-navy-mid`, `jvto-orange`, `jvto-orange-hover`, `jvto-lime`,
`jvto-gold`, `jvto-muted`, `jvto-border`). Colours **not** in the token set are Tailwind arbitrary values,
declared once in `homeDesign.ts`: `#FAF9F7` (paper), `#F1EFEA` (warm section), `#EFEDE8` (hairline),
`#CFCBC3` (rail button border), `#5A6472` (slate label), `#8A857C` (warm label), `#FF9A4D` (card meta),
plus the four PVMBG alert-chip palettes. Non-scale pixel values use arbitrary syntax throughout
(`text-[13.5px]`, `rounded-[16px]`, `px-[22px]`, `tracking-[-0.028em]`, `h-[158px]`, …).

**Fonts.** The export references `Bitter`, `Caveat`, `Raleway` and `JetBrains Mono`; none of Bitter or
Caveat are loaded by this site and no new font dependency was added. Per the brief, the mapping follows
what the codebase already uses: display/serif → `font-display` (`--font-display` → `var(--font-raleway)`,
matching the `Raleway, Inter, sans-serif` stack the old Home components used inline); mono → `font-mono`
(`--font-jetbrains-mono`); body → the default `font-sans` (Inter). The hero's Caveat accent line renders as
`font-display … italic` with the same size/colour/rotation, since no script face exists in the project.

### Other numbers that were checked rather than copied

- **Document hashes.** The block reads them from `src/lib/forensic-anchors.ts` (this repo's existing SSOT,
  already published on `/verify-jvto/legal` and `/llms.txt`) and truncates them programmatically to
  `first8…last8`. Nothing is re-typed. All five were independently confirmed against jvto-ekosistem:
  NIB `fa20dde3…f6f7b1b7`, TDUP `27252d51…11551ee3`, HPWKI `ca1fb1a4…98aaf63b` (organization.json);
  SPRIN POLPAR `03c8578d…6b145dfeab`, SPRIN WAL-TRAVEL `179b061e…3f8d6f3bd3` (people.json).
  *(The mockup rendered the two SPRIN hashes with a 10-char tail and the others with 8; the port uses a
  consistent 8/8 derived from the full hash.)*
- **"4 · Independent press articles"** (founder stat tile). **Not portable** — no data source in this repo
  backs "4": `forensic-anchors.ts` holds 2 press screenshots, and `/verify-jvto/press-recognition` counts
  them a third way ("Radar Jember ×2"). Rather than guess, the tile now reports a number that *is*
  derivable: `SHA256_ANCHORS.length` → "**7** SHA-256 anchored documents".
- **FAQ answers.** Rendered from `resolveFaqsForPage("/")` (the same `faqResolution.faqs` that builds
  `faqNode`), sliced to 6 — so the visible answers and the FAQPage JSON-LD can never disagree.
- **"Five landscapes, five levels of effort"** → `{destinations.length} landscapes, {distinct levels} levels
  of effort`, both counted from live data.
- **Package cards.** Name, origin→destination, duration, physicality label, highlights and `startFrom`
  price all come from the live listing. The mockup's "most booked" chip and its per-card
  "IDR x at 8–10 pax" line were dropped (no backing field). Card selection uses a preferred-slug list with
  a fallback fill from the live list, so a retired package leaves no hole and no stale name.
- **"11 years, one legal entity"** eyebrow → "Our story · one legal entity" (the year span was an
  unverified derived claim); the timeline's final row uses the **current year**, not a hardcoded 2026.
- **Story timeline rows 2015/2021/2023** are verbatim static copy about dated historical events that the
  repo already publishes elsewhere (Booking.com 2015 award, Detik/Radar Jember 2021 articles,
  TDUP 11 Feb 2023 / NIB 1102230032918).

## 5. Concerns / left unresolved

1. **Header & footer not rebuilt.** The export includes a nav bar and a footer, but on this site those are
   `Navbar` / `Footer` rendered by `src/app/(website)/layout.tsx` and shared by every route. Rebuilding
   them from the homepage export would restyle the whole site, which is outside "rebuild the homepage".
   They are unchanged; the hero was padded to clear the fixed navbar instead. Flagging in case the intent
   was site-wide.
2. **Dead components left in place.** `GoogleReviewsCarousel.tsx`, `GoogleReviewsCarouselClient.tsx`,
   `TourRowClient.tsx` and `ReviewsClient.tsx` are no longer imported by the homepage (and are not imported
   anywhere else). They were **not** deleted — that is a judgement call for review rather than something to
   fold into a redesign diff.
3. **`src/lib/jvtoReviews.ts` is stale.** Its `REVIEW_PLATFORMS` / `AGGREGATE_RATING` still carry
   Trustpilot 44 / Google 138 / blended 4.91 / 203, contradicting the ekosistem SSOT it claims to be
   derived from. The homepage no longer reads it, but other pages may. Worth a separate fix.
4. **"4 independent press articles" dropped**, replaced with the derivable anchor count — see §2. If a
   canonical press count exists somewhere I did not find, that tile can be switched back.
5. **Mobile is responsive, not pixel-designed.** Per the brief, the "4B" mobile states were not in the
   supplied export. Every section uses `md:` / `lg:` breakpoints and collapses sensibly (grids → single
   column, hero widget → stacked fields, rail → horizontal scroll), but this is not a ported mobile design.
6. **Fonts differ from the mockup** (Bitter/Caveat are not loaded by this site) — see the styling note in
   §1. Pixel-identical typography would require adding those webfonts.
7. **Live-DB rendering unverified.** Because no `DATABASE_URL` is available here, the DB-backed paths
   (`getDestinationsForHomepage`, `getWebPackagesList`, `getGoogleReviewStats`, the reviews query) were
   exercised with fixtures shaped from the **live production API responses**, not against the database
   itself. Worth one smoke test on a machine with the dev env file.
