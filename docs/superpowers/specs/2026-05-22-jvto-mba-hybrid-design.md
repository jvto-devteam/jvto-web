## Problem Statement

JVTO's website is technically healthy (strong AEO schema, 0 console errors, clean WCAG) but its visual design, page structure, and writing style lag behind industry reference Much Better Adventures (MBA). The goal is to adopt MBA's clarity and structural strengths while preserving JVTO's police-led differentiator and AEO/GEO entity graph.

## Premises (agreed)

1. MBA's visual approach (photography-first, minimal color, clean typography) is stronger for international adventure travel audiences than JVTO's current design.
2. MBA's content hierarchy (What's Included → What's It Like → Difficulty → Reviews → Dates) is clearer and more conversion-friendly than JVTO's current tour page structure.
3. Adopting MBA's writing clarity is compatible with JVTO's AEO positioning — provided we adopt clarity, not tone. JVTO's trust signals (POLPAR, NIB, BBKSDA) are the differentiators AI engines can't find in MBA. These are preserved and strengthened, not diluted.

## Approach: JVTO-MBA Hybrid

Adopt MBA's structural clarity and writing mechanics. Keep JVTO's design tokens (jvto-green, rounded cards), AEO entity graph, and police-led credential system.

Three deliverables: Visual Design Updates, Page Structure Templates, Writing Style Guide.

## Deliverable 1 — Visual Design Updates

### 1A. Typography — Rubik Test

Add Rubik (Google Fonts, rounded sans-serif) via `next/font/google` as an optional import. Test on hero H1 elements first (tour detail, destination, homepage). If visual feel improves, extend to all headings. System-sans remains fallback.

- File: `src/app/(website)/layout.tsx` — add:
  ```ts
  import { Rubik } from 'next/font/google';
  const rubik = Rubik({ subsets: ['latin'], variable: '--font-heading' });
  ```
  Apply `className={rubik.variable}` to the root `<html>` element.
- Declare in `src/app/(website)/globals.css` or equivalent:
  ```css
  h1, h2 { font-family: var(--font-heading, var(--font-sans)); }
  ```
- Revert condition: owner visual review after 2 weeks — if feel is not improved, remove import and CSS declaration

### 1B. Hero Sections — Photography-First

Reduce text overlay density on hero images. Current state: photo + badge row + long H1 + subtitle stacked. Target:

- H1 hero: max 6 words, bold white, centered or left-aligned on dark photo
- Trust badges: move from on-photo to first section below hero (remain visible, more readable)
- Gradient overlay: increase bottom gradient opacity for better text contrast
- Subtitle: optional — max 1 line, 12–14px, slate-300

Files affected: `TourDetail.tsx`, `DestinationDetailView.tsx`, homepage Hero component.

### 1C. Section Whitespace Rhythm

Standardize section padding across all website cluster pages:
- Major sections: `py-16 md:py-20`
- Secondary sections: `py-10 md:py-12`
- Tight info blocks: `py-6`

Currently inconsistent across tour detail, travel-guide, verify-jvto. No design token changes.

### What Does NOT Change

- `jvto-green` (#B2F35F) — accent color, distinctive
- `rounded-[24px]` on tour cards — JVTO visual signature
- Trust badge cluster (POLPAR, NIB, BBKSDA) — primary differentiator
- jvto-navy, jvto-orange, jvto-off — design palette retained

## Deliverable 3 — Writing Style Guide

### 3A. Headlines & H1

**Rule:** Max 8 words. Always include a metric (duration OR altitude OR distance) AND a differentiator (Private OR Police-Led).

| ❌ Before | ✅ After |
|---|---|
| "Bromo Ijen Madakaripura 3 Days 2 Nights Tour Package from Surabaya" | "3D2N Private Ijen & Bromo — Police-Led" |
| "Explore the Beautiful Ijen Crater" | "Climb Ijen Crater (2386m) in 2 Days" |
| "Mount Bromo Sunrise Tour from Surabaya or Bali" | "Private Bromo Sunrise — Jeep + Guide Included" |

### 3B. Body Copy Rules

- Max 2 sentences per paragraph
- Action verb at start of each sentence: "Hike", "Summit", "Descend", "Board", "Watch"
- Every factual claim has a number or credential inline
- Trust signals appear inline — not only in verify-jvto cluster

| ❌ Before | ✅ After |
|---|---|
| "JVTO provides an experienced local guide" | "Your guide holds an active Tourist Police (POLPAR) commission." |
| "We use comfortable vehicles" | "Private 4WD jeep, 3–4 pax max, air-conditioned." |
| "The tour includes all necessary permits" | "BBKSDA crater permit included — no hidden fees." |

### 3C. Inclusions Format

**Note:** `TourDetail.tsx` already renders inclusions as bullet lists (`.map()` over `pkg.inclusions` array). This is a **content-only edit** — no TSX change required. The task is shortening each string in the DB `inclusions` array to under 8 words, specific and credential-forward.

```
❌ CURRENT (verbose DB string):
"Transportation using a private air-conditioned 4WD jeep with dedicated driver"

✅ TARGET (concise DB string):
"Private 4WD jeep + driver (air-conditioned)"
"Gas mask rental — Ijen crater"
"BBKSDA crater entry permit"
"Tourist Police-coordinated guide"
"Hotel pickup & drop-off"
```

Update via CMS or direct DB edit — no deployment required.

### 3D. "What's It Like?" — Template

2–3 sentences. Focus on sensory experience. Trust inline but not dominant.

**Template:**
> [Physical/sensory detail of the journey.] [What the traveller sees/feels at the highlight.] [One JVTO-specific differentiator woven naturally.]

**Example — Ijen 2D1N:**
> "You leave Banyuwangi before midnight, arriving at the trailhead as stars are still out. The 3km ascent through sulfuric haze delivers you to the crater rim — blue fire visible below when conditions allow, the acid lake glowing turquoise at dawn. Your guide has made this climb hundreds of times and knows every weather signal."

### 3E. Forbidden Phrases

| Avoid | Replace With |
|---|---|
| "breathtaking experience" | Specific sensory detail |
| "world-class" | Metric or credential |
| "comprehensive package" | Bullet list of inclusions |
| "Blue Fire guaranteed" | "visible when conditions permit" |
| "mandatory health screening" | "health certificate may be required" |
| "seamless journey" | Specific logistics |
| "beautiful landscapes" | Named landmark + detail |
| "Our team" / "We provide" | Subject-first: "Your guide..." |

### 3F. AEO/GEO Compatibility Constraints

These assets must NOT be modified by this writing guide:

| Asset | Location | Reason |
|---|---|---|
| `narrative_claims` rows | Separate Prisma model, `primary_page`-wired | AEO-tuned brand claims C1–C9 — do not edit copy |
| `content_pages.content.faq` | CMS-editable per-route FAQ field | Lowest-precedence FAQ source — substance unchanged |
| FAQ copy | `src/lib/*Faqs.ts` | Feeds FAQPage schema — substance unchanged |
| Schema `@description` fields | `src/lib/schemas/build*.ts` | JSON-LD entity descriptions |
| Tour meta descriptions | `pageSnapshots.ts` + fallbackSeo | Already optimized per-page |

Only surface-level copy (tour body, inclusions list, what's it like section, heading text) is in scope for this writing guide.

## What I noticed

- JVTO's AEO architecture is genuinely stronger than MBA's — MBA has 0 JSON-LD on their homepage. JVTO's entity graph is a competitive advantage that most tour operators don't have. Any visual/copy improvements should be positioned as "JVTO catches up on surface quality" — the technical foundation is already ahead.
- The user's instinct to keep existing content (why-jvto, travel-guide, policy) rather than create new pages is correct. JVTO's content cluster is already deep — the gap is visibility and surface UX, not content existence.
- The "What's It Like?" section is the highest-leverage addition: it answers the emotional question before the logical one, which is MBA's core insight. JVTO's current pages answer logistics first.
